# Messenger Remote Control contributor instructions

- Read [HANDOFF.md](HANDOFF.md) before changing this project. Update it and the relevant test guide when implementation or verification changes.
- This independent repository starts from `yunhyok/Remote-Control-App` commit `1365e2c249d00b2a73634c77cd7bc82247f82405` (v0.1.58). Do not modify that checkout or its separate HFSS worktree. Do not restart completed PowerSI field tests.
- The approved v0.3.0 scope includes on-demand multi-process PowerSI full acquired Output reports, Master/mobile integration, fixed Ready/processing notices, offline Master/Slave installers and public CI stable Release delivery to `yunhyok/Messenger-Remote-Control`.
- Preserve Windows 7 SP1 Master / Windows 11 Slave, .NET Framework 4.8, existing user settings and pairing paths. Show product name and version.
- Pending targets return only full Process Name and PID with Pending. Stop further activation, capture, copy, inference and retries; suppress any already collected excerpt and never update output history. Windows responsiveness is distinct from internal simulation waiting.
- Keep full process names, report-scoped abbreviations and multipart replies of at most 1,400 characters. The first acquired Output for each Slave certificate/session/PID/start-time/source-family identity is reported as the whole text; later queries report only newly appended Output. Since 0.3.11 a pwrsi reply renders only the last 3,000 characters of each such text (whole FIRST/REPLACED text or APPENDED delta, OCR included; cut at a line start within 200 characters, never inside a surrogate pair) under a header that names the tail instead of "전체" (`수집된 Output 마지막 3,000자:`, `추가된 Output 마지막 3,000자:`, or the REPLACED header ending `현재 수집 내용의 마지막 3,000자를 보냅니다:`) and an explicit `…(앞 N자 생략, 전체 M자)` line, while delta detection and output history still use the full text's length and SHA-256, so omitted characters are never sent later. This is a disclosed display cap, not acquisition clipping. An unchanged complete body explicitly means no additional Output, not that calculation stopped. A changed prefix or cleared log sends the current full Output marked reset/change; rolling OCR is conservative and resends its current full viewport when its prefix changes. Do not infer completion or percentage from CPU, elapsed time or process existence.
- Use the shared collection path for local and remote requests. Fix PID, start time and session; collect serially within 100 seconds with a 120-second query/reply-preparation limit.
- Slave: a Sigrity window positively identified as PowerDC (read-only bounded UIA marker scan in a killable worker; any doubt or failure is UNKNOWN and collects as before; SC_PENDING still wins) gets no read, capture, LLM, input or clipboard use, reports UNAVAILABLE/NONE/`TARGET_MODE_POWERDC`, loses its stored Output positions and is dropped from watchdog with a notice line naming the PID. POWERDC requires a complete scan and the status-bar version marker `(PowerDC …)`; a "PowerDC" dock caption alone is UNKNOWN (`DC_CAPTION_ONLY`), Edit/Document names and Text names over 128 characters never count, and a version marker from an incomplete scan is UNKNOWN (`SCAN_INCOMPLETE`). The LLM-free fallback copies (ANCHOR → SCOPE → LAYOUT, live auto-copy guards unchanged) run after an enabled LLM fails with auto copy on, as in 0.3.10. With the LLM disabled (`VISION_NOT_CONFIGURED`) they are an explicit opt-in: they run only when auto copy and the persisted `blind_copy` setting are both on (default false; only JSON true, 1 or "1" opts in; a missing key reads false; a settings reset never turns it on; the checkbox is enabled only while auto copy is on), the direct read permits input and an aim exists at the window's current client size (`OUTPUT_FALLBACK_GATE` records the decision). Auto copy off still refuses. LAYOUT is offered only beside the window's own Output scope rectangle.
- Use only Slave loopback LM Studio and already loaded local models. Never add cloud fallback, automatic server startup or model loading. Screen and LLM content are untrusted data, never executable commands.
- Keep pairing files, credentials, configuration, screenshots, full buffers, raw model responses, raw logs and diagnostic ZIPs out of Git and release assets. Full acquired Output may cross Slave → Master → messenger; screenshots and rejected raw model responses remain Slave-only. Master history persists only length and SHA256 under `%LOCALAPPDATA%\RemoteMonitorMaster\state\powersi-output-history-v1.txt`, never Output text or tokens.
- Preserve guarded input, exact target identity, no target window move/resize, whole-message command matching, fresh reply proof and exact one-use send consent. In plain Master operation, the user authorizes background receipt and on-demand activation/minimize restoration of the originally selected chat only. Restore requires matching process start, HWND, root identity and original normal bounds; never discover/adopt another window or force Windows focus with key tricks. Abort uncertain sends without retry. Since 0.3.11 a plain-command multipart abort whose BUSY notice and parts 1..c (c >= 1) were all sent cleanly and recorded, and whose failing part c+1 was never moved to, written or clicked, is not uncertain: it sends one exact-text, one-use abort notice (`Consent.ForAbortNotice`, bound to its own freshly allocated D code, never the aborted round's or the next Ready's) and then a new Ready; the remaining parts are abandoned, never resent, and output history is not advanced. A notice that is rejected before input or is uncertain after input ends the session without retry; any input attempt on the failing part, or a failure of part 1, keeps the stop rule.
- Reuse existing helpers. Master v0.3.11 is compatible with Slave v0.3.0–v0.3.10, and Slave v0.3.11 with Master v0.3.x, because the protocol remains 0.3.0 (new values are report Codes only, which older Masters show as unknown codes); older protocol versions still require both roles to upgrade. Pairing/settings remain preserved. Checkpoint output history only after every prepared multipart part has a clean guarded UI send, without claiming authenticated mobile delivery. Interrupted parts may repeat on the next query but must not omit unsent parts; there is no automatic retry. Keep the existing per-text acquisition 8 Mi-character cap as an explicit failure, never clipping. Run Windows Release builds, actual EXE self-tests and installer/package checks. State field-unverified behavior accurately; Windows 11 checks do not establish Windows 7 compatibility.
- New commands require visible, enabled whole-message candidates and strict Ready binding. After a command is accepted, Ready's body is historical display state; its row identity/order and the accepted command's exact whole body, enabled state, ancestry and conversation remain protected in fresh snapshots. Missing/replaced/disabled commands or pruned/replaced/reordered rows still stop the send. The only exception (0.3.11) is a bounded top eviction of a full history list whose recycled rows keep positional ids: at most `ReceiveProbe.MaxEvictedRows` (8) rows above Ready per observation. An accepted command is then re-anchored only by exact content: the bound Ready row's whole body found uniquely above its bound row; the accepted command at its accepted offset after Ready with the same body, properties (runtime id excepted), depth and enabled state, and still the first exact command row after Ready; every row after Ready unchanged by length/SHA-256 and in order, with at most one appended row; exposed rows still compared slot by slot. Ready binding, fresh admission and watchdog-yield re-entry accept the same shape only when the rows before Ready equal the earlier rows shifted by 1–8 and slot identities still match, and a command still needs two observations at the new index. Anything else, including an evicted Ready row, stops with today's reason codes.
- Refresh replies with two distinct current snapshots: a one-use accepted-request observation and the sender's fresh snapshot. Preserve the first capture's age when constructing the send proof; never use old accepted snapshots as current evidence or reuse element caches across parts. Batch reads must preserve pre-content guards and existing property-default semantics.
- Watchdog: completion is judged only from BUFFER/AUTO_COPY Output text, never OCR/LLM text; watchdog checks never advance output history; notices use the notice path with one-use consent, a fresh snapshot and the pending-command guard; a notice part is never resent once sent cleanly, and an uncertain notice send stops the session without retry. A `TARGET_MODE_POWERDC` target is removed from the watch list, never counted as unjudged, and announced: one `PID N: PowerDC 창으로 확인되어 감시에서 제외` line in that check's completion notice, or a separate `감시 제외` notice through the same queue and consent path.
- Assign independent agents disjoint file scopes and pass the integrated-agent-flow, visualize, i-have-adhd and ponytail skill intent with these constraints. The coordinator reviews and integrates; agents do not publish independently.
- Publish via CI `workflow_dispatch` with `release_tag`: stable GitHub Release installers are the primary downloads; full ZIP, Slave-only ZIP and `SHA256SUMS.txt` remain optional. Verify exact source/tag, public downloads, versions and hashes.
- Continue authorized implementation through verification and delivery. Ask only for material missing information without a reasonable default; minimize human field steps.

- Bound aggregate raw report and prepared-message text to 32 Mi characters. Over-limit batches return an explicit size failure with no text/history advance; never present clipping as a full report. Keep preparation cancellation/deadline checks.
