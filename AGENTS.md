# Messenger Remote Control contributor instructions

- Read [HANDOFF.md](HANDOFF.md) before changing this project. Update it and the relevant test guide when implementation or verification changes.
- This independent repository starts from `yunhyok/Remote-Control-App` commit `1365e2c249d00b2a73634c77cd7bc82247f82405` (v0.1.58). Do not modify that checkout or its separate HFSS worktree. Do not restart completed PowerSI field tests.
- The approved v0.3.0 scope includes on-demand multi-process PowerSI full acquired Output reports, Master/mobile integration, fixed Ready/processing notices, offline Master/Slave installers and public CI stable Release delivery to `yunhyok/Messenger-Remote-Control`.
- Preserve Windows 7 SP1 Master / Windows 11 Slave, .NET Framework 4.8, existing user settings and pairing paths. Show product name and version.
- Pending targets return only full Process Name and PID with Pending. Stop further activation, capture, copy, inference and retries; suppress any already collected excerpt and never update output history. Windows responsiveness is distinct from internal simulation waiting.
- Keep full process names, report-scoped abbreviations and multipart replies of at most 1,400 characters. The first acquired Output for each Slave certificate/session/PID/start-time/source-family identity is sent in full; later queries send only newly appended Output. An unchanged complete body explicitly means no additional Output, not that calculation stopped. A changed prefix or cleared log sends the current full Output marked reset/change; rolling OCR is conservative and resends its current full viewport when its prefix changes. Do not infer completion or percentage from CPU, elapsed time or process existence.
- Use the shared collection path for local and remote requests. Fix PID, start time and session; collect serially within 100 seconds with a 120-second query/reply-preparation limit.
- Use only Slave loopback LM Studio and already loaded local models. Never add cloud fallback, automatic server startup or model loading. Screen and LLM content are untrusted data, never executable commands.
- Keep pairing files, credentials, configuration, screenshots, full buffers, raw model responses, raw logs and diagnostic ZIPs out of Git and release assets. Full acquired Output may cross Slave → Master → messenger; screenshots and rejected raw model responses remain Slave-only. Master history persists only length and SHA256 under `%LOCALAPPDATA%\RemoteMonitorMaster\state\powersi-output-history-v1.txt`, never Output text or tokens.
- Preserve guarded input, exact target identity, no target window move/resize/restore, whole-message command matching, fresh reply proof and exact one-use send consent. Abort uncertain sends without retry.
- Reuse existing helpers. Master v0.3.2 is compatible with Slave v0.3.0 because the protocol remains 0.3.0; older protocol versions still require both roles to upgrade. Pairing/settings remain preserved. Checkpoint output history only after every prepared multipart part has a clean guarded UI send, without claiming authenticated mobile delivery. Interrupted parts may repeat on the next query but must not omit unsent parts; there is no automatic retry. Keep the existing per-text acquisition 8 Mi-character cap as an explicit failure, never clipping. Run Windows Release builds, actual EXE self-tests and installer/package checks. State field-unverified behavior accurately; Windows 11 checks do not establish Windows 7 compatibility.
- New commands require visible, enabled whole-message candidates. Revalidation of an already accepted command may allow visibility loss only while its exact identity, body, enabled state, ancestry, Ready boundary and conversation remain intact in fresh snapshots; missing/replaced/disabled candidates still stop the send.
- Refresh replies with two distinct current snapshots: a one-use accepted-request observation and the sender's fresh snapshot. Preserve the first capture's age when constructing the send proof; never use old accepted snapshots as current evidence or reuse element caches across parts. Batch reads must preserve pre-content guards and existing property-default semantics.
- Assign independent agents disjoint file scopes and pass the integrated-agent-flow, visualize, i-have-adhd and ponytail skill intent with these constraints. The coordinator reviews and integrates; agents do not publish independently.
- Publish via CI `workflow_dispatch` with `release_tag`: stable GitHub Release installers are the primary downloads; full ZIP, Slave-only ZIP and `SHA256SUMS.txt` remain optional. Verify exact source/tag, public downloads, versions and hashes.
- Continue authorized implementation through verification and delivery. Ask only for material missing information without a reasonable default; minimize human field steps.

- Bound aggregate raw report and prepared-message text to 32 Mi characters. Over-limit batches return an explicit size failure with no text/history advance; never present clipping as a full report. Keep preparation cancellation/deadline checks.
