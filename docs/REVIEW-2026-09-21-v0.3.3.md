# v0.3.3 독립 소스 검토 결과 (2026-09-21)

[HANDOFF.md](../HANDOFF.md) §6의 점검 우선순위에 따라 공개 소스만으로 수행한 검토 기록입니다. 파일 범위를 겹치지 않게 나눈 여섯 검토(세션·창 처리 A, 수신 증거 B, 본문·이력·전송 C, Slave·통신 D, 화면 판독·빌드·CI E, UI/UX F)의 지적을 조정자가 소스에서 재확인해 통합했습니다. 행 번호는 v0.3.3 소스(`e31a67c`) 기준입니다.

- **구분:** 확정 = 소스에서 결정적으로 확인된 결함 · 가설 = 실행 환경/현장 조건에 따라 달라지는 지적 · 개선 = 기능/UX 개선 제안
- **처리:** 0.3.4 = 이 검토의 후속 변경에 반영 · 문서 = 코드 변경 없이 기록만 · 보류 = 현장 근거가 있어야 결정

## 1. 요약

계약(Pending, 정확한 명령 일치, 최신 두 관찰 기반 전송, 모든 부분 완료 후 이력 저장, 8 Mi/32 Mi 한도의 명시적 실패, loopback LM Studio 전용, 대상 창 이동·크기 변경 금지)은 여섯 검토 모두에서 **위반을 찾지 못했습니다.** v0.3.3의 Ready 본문 완화가 명령 변경·삭제·교체·재실행을 허용하는 경로도 발견되지 않았습니다(B 검토, `ReceiveProbe.EvaluateCore`의 `requireVisible` 분기와 `RequireHistoryPrefix`의 행 식별 비교).

## 8. 검사 공백 (E 검토)

1. Master `--self-test`는 Link 파싱 검사를 실행하지 않았음 → 0.3.4에서 순수 파싱 검사 추가. TLS loopback 검사는 계속 Slave 전용.
2. 실제 외부 창에 대한 `--powersi-screen` 캡처를 실행하는 자체 검사가 없음(자기 소유 창만).
3. 100%가 아닌 DPI 환경 검사 없음.
4. .NET 4.8이 없는 깨끗한 PC의 설치 경로(NDP48 실행, 1641/3010 재부팅) 검사 없음.
5. 설치 검사의 설정·이력 보존 단언은 CI에서 실질 검증이 아님(E15).
6. `TranscriptComparison`의 20,000줄 경로, OCR 뷰포트 스크롤 경계, 실제 LM Studio 스키마는 합성 검사만 있음.
7. `CoreSelfTest`의 폼 검사는 리플렉션으로 상태 기계를 검증하며 실제 이벤트 배선은 검증하지 않음.

## 9. 이 검토의 검증 수준

- 이 검토 자체는 Linux 환경에서 수행했습니다. Windows SDK가 없어 net48 참조 어셈블리로 별도 빌드했고(경고 0, 오류 0), Mono로 클래스별 `RunSelfTest`/`SelfTest`를 개별 실행했습니다. Windows API·UIA·WinForms·`CertificateRequest`가 필요한 단위는 실행할 수 없었습니다.
- Windows Release 빌드, 실제 EXE `--self-test`, 설치파일 생성·검사는 PR의 CI(Windows Server 2025)에 맡겼습니다. 실제 Win7 KI-Messenger, Win11 PowerSI, DPI 배율 환경은 여전히 현장 확인 대상입니다.
